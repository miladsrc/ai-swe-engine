# Progress — 2026-09-05

## Real Coder ↔ Verifier communication trace (committed 5f0a37d, 88a4380)

Goal: prove — live, not mocked — that the Coder and Verifier really
communicate through the engine API + git under SoD, and show exactly how.

### What was built
- **`SASE_ENGINE_TRACE=1`** opt-in `[comms]` tracing in `agents/engine_client.py`
  (`request()`): prints actor → method/path/compact-payload and ← HTTP status
  + compact response. Never prints headers (tokens). Body evidence
  (`execution_context`) is elided.
- **`scripts/trace_coder_verifier.py`**: end-to-end live demo. Seed chain
  (project/PRD/US/AC/spec, human-validated) → real `CoderAgent`
  (`qwen2.5-coder:7b`, `propose_only`) → git commit + AgentRun → orchestrator
  MRP (no tree hash) → immutable `POST /verification-requests` (run/mrp/commit/
  worktree) → `ci:verifier` subprocess `claim-next` → clean checkout → real
  pytest/scan/lint → evidence `PATCH` (audited `runner=ci:verifier`) →
  `complete` (tree hash) → orchestrator poll → G7 verdict → real `check-ready`.
  Retry loop `SASE_DEMO_ATTEMPTS` (default 3) with fresh spec per attempt.

### Three real bugs found & fixed (integration-level)
1. Claim response dropped `worktree_ref` → verifier `KeyError`. Fixed
   `api/schemas.py` + `api/routers/verification_requests.py::_row_to_schema`;
   API image rebuilt.
2. `EngineClient._assert_allowed` only supported trailing `*`; verifier's
   `POST /verification-requests/*/complete` and reviewer/critic
   `PATCH /mrps/*/review` were blocked client-side. Mid-path `*` now matches
   exactly one path segment (`[^/]+`); trailing `*` = subtree preserved.
3. `_pseudo_pr_number` collisions in the 30k space (verified: two real
   `(spec_id, run_id)` pairs both → 71885 → HTTP 409). Now
   `70000 + int.from_bytes(sha1(f"{spec_id}|{run_id}")[:4]) % 30000`.

### Results (live, strict mode)
- Full communication loop works end-to-end; every message above visible in the
  `[comms]` trace.
- G7 **ACCEPTS**: `MRP.verified_tree_hash` == verifier evidence tree hash
  (`ce8aee59…` on the last attempt), audit row owned by `ci:verifier`.
- Real `check-ready` returned `ready=False` correctly: `unit tests not passing`
